# Adventures Rest

- Design doc (Claude Doc): https://claude.ai/code/artifact/dff8e88a-ef18-4a41-8715-186a982a81c3
- Stack: C# + Godot 4. The C# sim lives in `dotnet/` (no Godot dependency); the Godot client in `godot/`.
  The TypeScript sim in `src/sim` and its web build are frozen as the legacy web build (own data copy in
  `src/sim/content/`); sim changes land in C# only. Builds are published so they can be played from the Claude
  project. The owner never opens GitHub, an engine or any other tool: show progress as summaries, Ledgers, screenshots and playable builds.
- Decided: real time with pause on top of a daily strategic tick.
- Priorities: low-cost scalability, efficiency, speed, quality, style.
- Future expansion (not built): the underdark and other planes (fey, hells, space) as separate giant map layers
  reached by ancient portals found on the map or portals the player builds late and must guard. See `docs/map-layers.md`; don't hard-wire "one map".

## Working here

- Node 22.18+ runs `.ts` directly (type stripping), so only erasable TypeScript: no `enum`, no
  `namespace`, no constructor parameter properties. Import with explicit `.ts` extensions.
- `npm run typecheck`, `npm test` and `dotnet test dotnet/CrownAndCompass.sln` must pass.
- C# kept the TS logic shape (same function order and names, PascalCase). JS number semantics go through
  `Js` (`Js.Round`, `Js.ToFixed`, `Js.Str`, `Js.Hypot`, `Js.Sum`); sorts use LINQ `OrderBy`/`ThenBy` (stable,
  like JS); maps whose order matters use `OrderedMap`; watch int division where JS divides doubles.
- Determinism matters: every random call goes through `town.rng` (`Town.Rng` in C#), and decisions iterate agents and
  buildings in id order. Sorts must break ties by id.
- Judge sim changes by reading the Ledger across several seeds
  (`dotnet run --project dotnet/src/CrownAndCompass.Cli -c Release -- --days 120 --seed N`), not one run.
- Gameplay numbers live in `content/game/*.json` where possible.
- Save/load (`Save.cs`) writes every field of the sim by reflection, so new state is saved without touching it, and
  `SaveTests` checks a reloaded campaign replays the same Ledger. Mark listeners and caches `[NotSaved]`, keep no
  delegates in sim state, and never depend on `Dictionary`/`HashSet` iteration order (saves write them in key order).
  Content is saved by key, so renaming a content id breaks old saves. CLI: `--save f.save`, `--load f.save`.
- The rest of `content/` is the SRD + open third-party + original content library, with real-time `rt` hints. The C#
  sim reads its classes, monsters, spells and magic items (`Library.cs`); game files refer to library ids
  (`"ref": "goblin-warrior"`) instead of copying stats. `srd/` and `open/` are generated by `npm run content:import` (`vendor/` holds itch.io packs converted by
  `scripts/convert-itch.ts`); hand-write new material in `content/original/`.
- Lore check: the world's history is `content/game/history.json` (lore doc: https://claude.ai/code/artifact/e963507b-1cdf-4ce2-9e5a-cf06bb727a6c).
  Every menace kind, people, faction, hero background and institution needs a `lineages` entry there naming the power it descends
  from and its motive; menaces add themes and ambition weights, backgrounds the classes that come up through them, and
  either can add traits. `LoreTests` fails on anything without one. Use original names only, never a WotC setting's.
- Across campaigns: the client's profile `user://profile.json` (`godot/src/Profile.cs`) is the one store for anything
  that carries between runs; each feature owns a section (`legends` now). The sim never reads it: the client passes it
  in `SimulationOptions` (`Legends`), and the town keeps what it used in saved state. Turncoats and returning legends
  are `Systems/Turning.cs` with numbers in saga.json `turning`.
- The mayor (`Systems/Stories.cs` sheet, `Systems/Regalia.cs` gear, `Systems/Mayoralty.cs` life, numbers in `regalia.json` and
  `mayoralty.json`): rolled on New game (`SimulationOptions.Mayor`), wears regalia from the armory, and is a person with hit points and a
  stance (`keep` safe, `town` exposed to assassins and breaches, `ride` with the next company out). A dead mayor is raised at the temple
  or succeeded by one of three rolled candidates; `SimulationOptions.Hardcore` makes death a defeat. Its rolls use its own dice, never `Town.Rng`.
- Notoriety (`Systems/Notoriety.cs`, numbers in `content/game/notoriety.json`): heroes (`HeroSheet.Renown`, `Infamy`,
  `Epithet`) and companies (`CompanyState.Renown`, `Infamy`) earn fame or infamy through `Notoriety.Deed`/`CompanyDeed`;
  new deeds that should make a name call those rather than adding to `Renown` directly. Stories bind them with the
  `famous`/`infamous` needs.
- Clock stops: nothing calls `SetSpeed(0)` for an event. Each kind of event that may stop the clock is one line in
  `godot/src/ClockStops.cs` (`ClockStops.All`: id, label, tip, default) and its site calls `Main.StopClock("id")`; the
  player toggles each in Settings (`godot/src/Settings.cs`, profile section `settings`). Only menus, the title and the end screen pause directly.
- Alerts (badges on the left rail): raise one from the sim by adding a kind and a rule in `Systems/Alerts.cs`
  (rules read the town, never write or roll dice; an alert lasts while its rule names it). Each alert is one action for the player; news goes to the Ledger, not the alerts.
  An alert badges the rail button of its `AlertWindow` (kinds with none map in `Dock.RailOf`; stories go to the Events tray), and hovering
  the button lists them (`ShowRailAlerts`; `--alert-hover N` pins the Nth). There is no top strip any more. A new urgent or decision alert also slides a tile out of its window's rail button
  (`godot/src/RailNotices.cs`, `--notices F` replays the standing ones for shots); it reads the same alerts, so add nothing there.
- Institutions (`content/game/institutions.json`, `Systems/Institutions.cs`, client `godot/src/Institutions.cs`): a
  civic building with a keeper, a daily service (a `DecreeDef` plus defence, heroes, healing, escorts, routes, faction
  standing), patronage levels, one mayor's choice and fixtures stories leave. Requests are ordinary stories in the same
  file that need `institution:id[:choice]` and use `goodwill`/`goodwill2`, `fixture:id` and `{keeper}`/`{institution}`; a
  story naming two institutions binds both. Services hook in at their call sites (Brain, Economy, Population, Threat,
  City.HeroCap, Trade, Shrines), not through Decrees.
- Density (`Systems/Density.cs`, city.json `densities` and `sprawl`): low/medium/high per plan cell (`LandPlan.Density`), painted
  with homes and shops (`PaintZone(..., density)`, also over built land of the zone). `BuildingDef.Density` is the least a building
  needs (townhouse/manor medium, tall_house high); `HousingDef.Dense` is the house it grows into on high land; high land drops
  the lane between buildings. The stand-in mayor zones denser out to `reach * sqrt(population)` tiles, capped by `WardDef.Densest`.
- Growth and construction (city.json `growth`, `construction`, `Systems/Construction.cs`): painting lays no streets. Buildings
  site on street fronts or off them beside what's built (`Streets.Growth`, nearest the built town first), and the feet going to
  them wear lanes (`Streets.Wear`). The townsfolk's builds on painted land wait for a free crew (`Construction.Room`), and a site
  can't rise past its footings until builders haul its timber and stone (`Building.Hauled`, `Activity.Hauling`); labour budgets
  use `Construction.Hours`. The client draws sites rising in six steps with a materials pile, haulers carrying loads, and a hired
  hand at sites nobody in town works (`--rising` aims at one). Crews come from builders' yards (`BuildingDef.Crews`,
  `Construction.Crews`; the stand-in mayor adds one below `Construction.Wanted`), whose builders work the nearest site
  (`Construction.SiteFor`). A house grows a storey only with `HousingDef.Near` services within `nearReach`, `Foods` kinds of
  food and `Beauty` appeal (`City.NeedsBlocked`).
- Lodging (`Systems/Lodging.cs`, `content/game/lodging.json`): newcomers off the road are travellers (`Agent.Traveller`: out of
  `Population`, never `Homeless`) who take a room (`BuildingDef.Rooms`: tavern 4, inn 12) or camp, settle once they hold a job, a
  home or a building, and otherwise move on at `StayUntil` saying why. `Lodging.Nightly` beds heroes first, then travellers; a hero
  camped `campNights` in a row rides on unless the town binds them (knight, fief, bastion, duty). Client: tents at `Lodging.Camp`
  (`Crowd.Tents`), arrivals walk in from `Lodging.Road`.
- Refugees (`Systems/Refugees.cs`, `content/game/refugees.json`): every blow that drives folk out of a settlement or a
  menace's way calls `Refugees.Flee(town, from, by, range)` (never `Population.Settle`); its size is times `Refugees.Draw`
  (walls, Mandate, haven fame, less dread). They are travellers with `Agent.Refugee`, camp free, wait `patience` days (longer
  while homes or workplaces rise) and settle like any traveller; settled ones never leave for misery. A column of `cardAt`+
  waits on the `refugee-column` story (`Town.Refuge.Column`, effect `shelter`). Sheltering earns Mandate, the people's thanks
  and haven titles (`havens`). They name the site that took their home (`Refugees.Remember`, `Town.Refuge.Lost`; pass `siteId` to
  `Flee` when the blow has one) and an exiles' plea stands to retake it; when it is cleared or their menace falls, those still
  camped go home and a razed village rises again, allied.
  Shots: `--refugees N`, `--story refugee-column`.
- Zone layouts (city.json `markets`, `closes`): each zone grows its own way. Shops: `Streets.Markets` lays a rectangular
  market square (`Street.Market`) in shop paint with a straight high street to the nearest street, once the town keeps
  `shopsEach` shops per square; shops front its rim first, a side all facing one way. Homes: `Streets.Closes` lays a wandering
  side lane (`Street.Close`, never paved) from the deepest open home paint. Fields are client-side (`TownView.Fields`): each
  farm works the farmland nearest it in rows the way it faces, hedgerows on the bounds, a farmstead only on the oldest farm per
  2.6 tiles. The zone brush shows paint only, never outlines of buildings to come. `--zone farmland|commercial|residential|square|camp` aims shots.
- Monuments (`Systems/Monuments.cs`, parts in buildings.json with `partOf`, `after`, `favour`): the town hall, temple and keep
  grow by parts, each its own civic building beside the core (`Building.ParentId`) with its own bonuses and a daily `favour`
  with the god (`"god"`) or a faction (`"faction:id"`, negative for a rival). `Building.Grow` lets the council add the cheapest
  next part from spare gold; `AddAllParts` builds big at once. Council sites (`Building.Draws`) take their timber and stone off
  the market's stock as hauled and stall when it's out (`Construction.Stalled`, the `stalled` alert, `SendCaravan`);
  `Building.Priority` sends builders and materials to a site first. Client: `Map/MonumentMeshes.cs`, the card in `Panels.cs`
  (`--at temple --card` shows it).
- Paving (`Systems/Paving.cs`, city.json `paving`): no player-laid paving. From the `tier` charter the masons cobble streets
  on their own, nearest the centre first, `perDay` tiles from the market's stone stock (never imported) and the treasury above
  `reserve` (`Street.Cobbled`, `FromEnd`). Houses near cobbles gain `comfort`; the client draws them from the ground texture's blue
  channel.
- Drawn walls (`Systems/WallLines.cs`, city.json `wallLines`): the player draws each wall's loop (`Simulation.DrawWall`, ring 0
  the palisade/stone walls, ring 1 the city wall) and snaps gates onto it (`PlaceGate`, `RemoveGate`; at least one, the first
  is the main gate). `City.Wall` reads the drawn line, so the clear strip, `Passage` openings, raids and the client follow it;
  an undrawn line makes way for the other's. Walls draw their timber and stone daily (`Threat.Haul`) and slow when short
  (the `stalled:walls` alert). Shots: `--draw-wall 0:x,y;x,y;... --gate 0:x,y` (tiles from the centre).
- Wards (city.json `wards`, `unsettled`, `rings`): never laid out by hand. The charter opens rings (`City.RingOpen`); a quarter
  (ring + side) with `founding` finished buildings becomes the ring's ward its buildings draw most (`WardDef.Draws`, `City.Form`,
  `CityState.Sectors`). The map outlines a ward round its own buildings. `City.Migrate` maps old saves' wards to their quarters.
- Crowds (`Systems/Crowds.cs`, numbers in `content/game/crowds.json`): every building townsfolk go out to has a `capacity`
  in buildings.json (`CrowdsTests` fails one that serves them without). Outings (drinking, praying, `Activity.Visiting` a
  bathhouse/theatre/market hall/library/arena) go through `Crowds.Enter`: a full door turns them to the next place near or back
  to choosing their hour (`Agent.TurnedFrom`). Yesterday's turned-away share cuts the service's coverage, adds to demand and
  raises the `crowded` alert. Counts are kept once an hour (`Crowds.Begin`/`Moved`), so keep door checks O(1).
- Passage (`Systems/Passage.cs`, `content/game/passage.json`): nobody crosses walls, the moat, the river, lakes or peaks
  on foot except at an opening. Town walkers route through gates with `Passage.Next` (the client's `Crowd` uses it), lanes
  skip the wall bands (`Passage.Mask`), and every walled section must keep an opening (`Passage.Sealed` stays empty). The
  river and its fords and bridges come from the sim (`Passage.River`, `Crossings`); roads.json kinds with a `barrier` are
  skirted unless the party has the way across (mounts, spells, items in passage.json; `Passage.Abilities`). Townsfolk
  only swim the moat or climb the wall when fleeing a raid next to them (`Passage.Fleeing`), never to get to work.
  The Sky Dock institution (`sky-dock`, service `airship`) lends a company its airship when its road meets what it
  can't cross (`Passage.Board`, `Party.Airship`), one company at a time; trade runs build on the same ship.
- Storytellers (`content/game/storytellers.json`, `Systems/Storyteller.cs`): the difficulty, chosen on New game (`SimulationOptions.Storyteller`,
  kept as `Town.Storyteller`; CLI and client `--storyteller id`). Pacing code multiplies its levers by `Storyteller.*`; Rising is all 1s
  with no swing and must roll nothing, so gate sweeps stay put. Moods (`content/game/moods.json`, `Systems/Moods.cs`): townsfolk high for
  days get a trade inspiration, low ones break (`Agent.Episode`, shown as street bubbles and in the inspector; `--episode id` stages one).
  Their rolls use `Moods.Dice` (seeded from seed, tick and person), not `Town.Rng`, so moods never shift the main stream.
- Acts and the final horde (saga.json `acts`, `horde`; `Systems/Saga.cs`, `Systems/Horde.cs`): an act opens when the town is strong
  enough (`OpensAtLevel` champions and `OpensAtPopulation`, times `Storyteller.Acts`), after its `minDays`, or after `maxDays` regardless.
  The big bad's host gathers at its seat and holdings (`HordeState.Camps`), musters, then marches; fights at a camp thin it, a cleared
  holding scatters it. The town learns its size and moves only with eyes on its camps or road (`Horde.Eyes`, `RoadWatched`), else a day
  or two out; nothing shows a count of days for it (`Horde.Word`). Its first breach burns the lower town (`Horde.Reprieve`); the next falls it.
- Decorations (`content/game/decor.json`, `Systems/Decor.cs`, client `Map/Decorator.cs`, `Map/DecorView.cs`): free positions in
  tiles from the town's corner and any angle (radians, model front +Z turned by it). Every piece needs a small effect in
  another system, capped in decor.json. Pieces claim plan cells (`Decor.Cells`, `LandPlan.Decor`): `Land.Fits` and lanes go
  round them, and they never stand on a lane. Appeal adds to house contentment (`Decor.Comfort`) and to ward land prices
  (`Decor.Prestige`). `--beautify D` dresses a town for screenshots; `--decor oak --decor-at x,y,a` shows the tool.
- UI text (`docs/ui-text.md`, kit in `godot/src/UiKit.cs`): Conner wants little text. Icon before word (`Ui.Chip`), one point a
  line (`Ui.Bullets`), explanations in hovers (`Ui.Tip`, `Ui.Brief`; `Pane.Note` briefs itself), colour by meaning, short labels.
  Every pane heading has an icon (`Ui.HeadingIcons`); every god has `god-<id>`. New icons go in `scripts/icons.ts`.
- Menus: the left rail (`godot/src/Dock.cs`) is six coloured groups (`Groups`: Town, Council, Heroes, War, Realm, Lore;
  Shift+1 to 6); a group opens one window with its windows as tabs along the top (`TabNames`, `Blurbs`). A new window is a
  tab in a group, never a new rail button. Rail buttons and tabs badge the alerts whose `AlertWindow` they answer, so a new
  alert badges its window for free. Long windows split into pages (`Pane.Page`, `--page Name` for shots; tutorial points
  `tab:Council:Laws`); headings fold on click (`Pane.Folded`, kept in the profile's settings) and a heading with nothing
  under it is dropped, so don't print "nothing yet" lines. Window headings sit on a band in the group's hue (`Pane.Hue`);
  long how-it-works notes go in one `Pane.Help` hover. The Build bar sorts by kind (`BuildGroup` buckets, `BucketOf`,
  `CivicBuckets` in `godot/src/Build.cs`): zone brushes, then buildings, hiding any more than one charter tier ahead. The action tray on the
  right (`godot/src/Tray.cs`: Bounties, Council, Events, War) slides out a drawer to act without a window. The top bar's
  monthly trends and hover cards read `Systems/Trends.cs` (30 days of books, food, Mandate, unrest; numbers in trends.json).
- Godot client in `godot/` (Godot 4.3 .NET). Screenshots: `xvfb-run -a godot --path godot --rendering-driver opengl3
  --resolution 1600x900 -- --seed N --day D --autoplay --screenshot out.png` (`--cam`, `--look`, `--site`, `--strategic`
  aim it; `--bench` checks the performance budget in the GDD). Exports go to `godot/build/` (ignored).
- Tutorial: `content/game/tutorial.json` teaches every player-facing feature, and `TutorialTests` fails when a player
  command on `Simulation`, a dock tab (`Tab` in `godot/src/Main.cs`) or a client hotkey has no step whose `teaches` lists
  it (`command:PostBounty`, `tab:War`, `key:B`). So a PR adding a feature adds or updates its step in the same PR. The tour is the steps up to `done` (at most 25, `Tutorial.TourMost`); a new feature appends its step after
  `done` as a tip with a `when`, never into the tour (TutorialTests checks both). A step
  can outline part of the HUD (`point`), wait for the player (`until`: a client event, `tab:X`, or `count:<any Town
  list>`) and hold back until it is relevant (`when`: `count:X`, `day:N`, `alert:<key>`), so new systems rarely need
  client code (`godot/src/Guide.cs`). Keep step ids stable: players who finished the tutorial are shown steps with new
  ids as "New in this build". Early-game direction is the charter goals (`content/game/goals.json`, `Systems/Goals.cs`):
  each goal's `point` (any tutorial anchor, `tab:X`, `zone:<Zone>`, `place:<building>`) rings the button for the next goal with an
  arrow whenever no tutorial step is showing (`SyncGoalPointer` in `godot/src/Guide.cs`). The main menu is `godot/src/Title.cs` (`--title`, `--tutorial start|<step-id>` for shots).
- Look: the painted style is the default (`MapView.Painted`: cel bands in `light()` via `cel()` in common.gdshaderinc, ink outline
  `ink.gdshader` as the props/foliage next_pass, glow, haze; `--style classic` for the old look, `--clean` hides the HUD in shots).
  MeshKit faces must wind outward (the outline inks inside-out parts black). Homes are modelled in Blender from code
  (`tools/blender_houses.py`, Blender as a pip module: `python3 -m pip install bpy`) and baked to `models/crafted.bin` in the
  kenney.bin layout; roof faces bake as (255, 0, shade) and `TownView.RoofPaint` colours them.
- Enemy groups (`content/game/groups.json`, `World.PickGroup`, `Content.Group`): ready-made foes (sewer infestation, frozen pass,
  witch hunters...) that hold sites of their own in the themes they name, with their own foes, bosses and a history.json lineage
  (subject `group:id`, or an existing enemy's lineage for a version of it). A cleared group site is retaken by its own bosses.
  Monster names: SRD/CC-BY or originals only; WotC-only creatures get an original name and look (report https://claude.ai/artifact/RLbN5w9GFQ976uamUqgPDw).
- First meetings (`content/game/intros.json`, `Systems/Intros.cs`, client `godot/src/Intros.cs`, `Vignette.cs`): every history.json
  lineage a town can meet (menace, foe, group, people, faction) has one line there: a scene, a host look, colours, a crest glyph
  (`crest-<lineage>` from `scripts/icons.ts`) and a short line. The card stages the host live with the heroes' kit (creature bodies:
  `Frame.Spider`, `Wyrm`, `Wraith`, `Crawler`, `Rat`) and shows once per lineage (`Intros.Due` over `Town.Discovered`; clock stop
  `first-contact`). `IntrosTests` fails a lineage without one. Shots: `--intro <lineage>`.
- Fights (`Systems/Prowess.cs`, `Systems/Expedition.Prowess.cs`, numbers in `content/game/prowess.json`): heroes gain Extra Attack
  (library class features), cantrip dice and spell slots by level; casters pick from prowess.json `spells` each turn (the library gives
  dice, damage type and save); class powers are `powers` entries played by id. Every blow on a foe goes through `Venture.Hit(foe, dmg,
  type, magic, silver)`, which applies the library's resist/immune/vulnerable and stops regeneration; new damage (item powers) goes
  through it too. Foes pick whom to hit by their Intelligence (`Venture.Victim`). Fights in the open feel the sky (`Venture.Sky`, set by Roads, Explore and the battles at the walls from `Weather.At`/`Here`;
  prowess.json `weather`): lightning harder in a storm, rain, wind and fog off ranged shots; sites of `cover` habitats are fought indoors.
- Lair towers (`Systems/Lairs.cs`, lairs.json `outpost`/`patrol`): a cleared site is kept clear by a patrol (a lost fight wounds
  the hero) or a tower built over `buildDays` (`SiteState.TowerDue`, then `Held`), tested now and then on the site's own dice
  (`Lairs.Tested`, `Reinforce`, alert `tower`). A knight's fief is theirs: `Loyalty.Choose` sets `HeroSheet.FiefWay`
  (tower/ride/rent) and the town gets no buttons there. Shots: `--tower rising|standing|tested`.
- Painted zones (`Systems/Wilds.cs`, `content/game/wilds.json`; client `MapView.Brush`, `Overlay.DrawWilds`, the Explore and Patrol
  quick orders, Bounties folds): the mayor paints cells of the wilds. Explore paint posts an ordinary survey commission
  (`Explore.PostZone`, `Commission.ZoneId`) again after each trip until every cell is `Seen`, then fades. Patrol paint stays until
  rubbed out: a daily wage per cell (less what a horse regiment riding it covers, `Regiment.WildsId`, away from the walls), raids cut and
  security added on roads through it (`Wilds.Road` in `Neighbours.RaidShare`/`SecurityTarget`), lair and menace raids seen sooner
  (`Wilds.Warns`), meetings rolled on its own dice. Old caravan patrols migrate into it (`retired` in neighbours.json); lair patrols
  stay their own order. The region list and the spot click are gone from the UI (`PostSurvey`/`MarkSpot` stay for the stand-in and old saves).
- Weather (`Systems/Weather.cs`, `content/game/weather.json`): a pure function of the seed and tick (`Voices.Hash`, never
  `Town.Rng`; only `WeatherState` is saved). Pressure fronts drift on the prevailing wind over seasons and climate; read it with
  `Weather.At(town, x, y, tick)` (days from the town, x east, y south), `Here`, `Worst`, `Ground` (snow lying, wet ground),
  `Forecast`, `StormIn`. Steps Fair/Grey/Foul/Storm/Tempest; airships, sky trade and marches (`Weather.MarchDays`) read it.
  Roads (weather.json `road`): `Roads.Weathered` slows each stretch by snow, mud and storms (`Weather.Slow`), fog and storms add
  navigation DC (`RouteMind.Murk`), fords in spate send parties to bridges (`Weather.Flooded`), killing nights call for saves
  and shelter (`Weather.Exposure`, `Venture.Exposed`), all on their own dice; story need `stormbound`.
  Town (weather.json `harvest`, `damage`): `Weather.Harvest` leans farm yields (influences, never decides; about even over a
  year), storms with a gale wreck timber and lightning fires it (`Blows.Wreck` sets `Building.Wrecked`); `Town.Repairs`
  (`Simulation.SetRepairs`: crews/first/hire, `Construction.Mend`) is how damage from any cause is mended.
  Storm lords (weather.json `lords`): sites whose master is listed (storm giants, blue dragons, cloud giants, hags, frost giants,
  white dragons) work storm, fog or winter round their lairs (`WeatherState.Lords`, refreshed each morning) and some call storms
  at the town or a company (`WeatherState.Called`); `WeatherNow.By` names who. Answers: `wardens` research, a high druid at
  home, `tamed` research for harvests, `glass` research for the forecast. Bump `WeatherState.Version` when you change either list.
  Client: `Map/WeatherView.cs` (sky, rain, snow, lightning, shader `gale_wind`/`wet_ground`/`snow`), the campaign-map layer
  `Map/WeatherLayer.cs` (off by default, a toggle by the corner map), the top-bar chip `WeatherHud.cs`; clock stop `storm`.
- Cliffs (`Systems/Cliffs.cs`, passage.json `cliffs`): plateaus in the near wilds past the plan, a pure function of the seed. Passage
  treats each as a barrier opened only at its ramps (`Passage.Obstacles`, `RoundCliffs` for roads); the client raises them
  (`WorldGen`) and faces them with rock (`WorldView.BuildCliffs`).
- Art: only CC0/CC-BY or our own; credit every pack in `godot/assets/CREDITS.md`. Kenney models are baked by
  `python3 tools/kenney_bake.py` into `godot/assets/models/kenney.bin`. Shader colours are sRGB converted once in the
  shader (no `source_color` hint). Client decoration randomness goes through `Geo.Hash`, never the sim's rng.

## Merging and publishing builds

- The merge gate is `node scripts/gate.ts` (CI jobs `gate-sim` and `gate-client`). On a PR it merges the latest main in
  first, then runs the unit tests, a 12-campaign 1,000-day sweep compared with `dotnet/gate-baseline.json` (fails if
  wins or defeats move by more than 3, the median ending moves over 20%, or a campaign ends far sooner), a save/load
  replay, a save written by main that must still load and play on, and the exported Linux build played from the main
  menu with `--smoke` (new town, every window, build bar, campaign map, save and load, tutorial, History) failing on
  any engine error. A PR that adds a window or screen adds it to `godot/src/Smoke.cs`.
