# Adventures Rest

- Design doc (Claude Doc): https://claude.ai/code/artifact/dff8e88a-ef18-4a41-8715-186a982a81c3
- Stack: moving to C# + Godot 4. The C# sim lives in `dotnet/` (no Godot dependency; a Godot client comes
  next). The TypeScript sim in `src/sim` and its web build stay as the parity reference until the Godot
  client replaces the web build: both must print byte-identical Ledgers (`scripts/parity.sh`), so a sim change
  lands in both. Builds are published so they can be played from the Claude project. The owner never opens
  GitHub, an engine or any other tool: show progress as summaries, Ledgers, screenshots and playable builds.
- Decided: real time with pause on top of a daily strategic tick.
- Priorities: low-cost scalability, efficiency, speed, quality, style.

## Working here

- Node 22.18+ runs `.ts` directly (type stripping), so only erasable TypeScript: no `enum`, no
  `namespace`, no constructor parameter properties. Import with explicit `.ts` extensions.
- `npm run typecheck`, `npm test`, `dotnet test dotnet/CrownAndCompass.sln` and `scripts/parity.sh` must pass.
- C# mirrors the TS logic shape (same function order and names, PascalCase). JS number semantics go through
  `Js` (`Js.Round`, `Js.ToFixed`, `Js.Str`, `Js.Hypot`, `Js.Sum`); sorts use LINQ `OrderBy`/`ThenBy` (stable,
  like JS); maps whose order matters use `OrderedMap`; watch int division where JS divides doubles.
- Determinism matters: every random call goes through `town.rng` (`Town.Rng` in C#), and decisions iterate agents and
  buildings in id order. Sorts must break ties by id.
- Judge sim changes by reading the Ledger across several seeds (`npm run sim -- --days 120 --seed N`), not one run.
- Gameplay numbers live in `content/game/*.json` where possible.
- The rest of `content/` is the SRD + open third-party + original content library (inspiration, with real-time `rt`
  hints). `srd/` and `open/` are generated by `npm run content:import`; hand-write new material in `content/original/`.
